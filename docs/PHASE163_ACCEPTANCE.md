## Reuse and authority

This extends `PaperExecutionAdapter`, `SimulationEngine`, `SimulationService`
and the Phase 16.2 historical runner. There is no second execution engine,
worker, admission slot, queue, runtime strategy or execution endpoint.
Historical requests still use `POST /api/v1/historical-replay/run`, the existing
single-slot `SimulationExecutor`, and the optional Redis coordination wrapper.
Baseline and modeled segment runs execute sequentially inside the same admitted
operation. Cancellation detaches the HTTP waiter while that slot stays occupied
until actual completion; shutdown waits for both passes.

Every engine invocation constructs fresh PAPER orders, inventory, history,
telemetry, risk authorization and accounting. Operational strategy, reference
services, signer adapter, risk settings, kill switch and accounting state remain
unchanged. Existing quote validation and final authorization remain authoritative.
Modeling never supplies an absent reference to obtain permission to trade.

## Strict versioned assumptions (16.3A)

`PaperExecutionAssumptions` is frozen, rejects unknown fields, requires strict
integer/boolean controls and finite exact Decimal financial inputs (decimal
strings on JSON). Floats, booleans as numbers, nonfinite values, exponent strings,
excess decimal places and out-of-range controls reject. Worker/engine and adapter
boundaries revalidate serialized controls, including forged `model_copy` objects.

| Field | Default | Bound / meaning |
| --- | --- | --- |
| `version` | `phase163-v1` | Code-supported contract version only |
| `mode` | `BASELINE` | `BASELINE` or `MODELED_CROSSING` |
| `order_latency_ms` | 0 | Integer 0–60,000 |
| `cancel_latency_ms` | 0 | Integer 0–60,000 |
| `slippage_bps` | `"0"` | Exact Decimal 0–1,000; adverse per-level price adjustment |
| `depth_sensitive` | false | BBO-only budget, or walk retained L2 levels |
| `allow_partial_fills` | true | If false, require the full remaining size within the available budget |
| `participation_rate` | `"1"` | Exact Decimal 0–1; fraction of observed level size available to the model |
| `max_fill_fraction` | `"1"` | Exact Decimal 0–1; fraction of remaining order size per book observation |

Baseline rejects nondefault model controls rather than silently ignoring them.
Its original immediate submit/resting crossing behavior, full size, limit-price
fills and existing maker/taker labels remain unchanged. Default simulator run
fingerprints remain unchanged. Results add assumptions metadata; new replay
configuration and receipt identities bind the expanded contracts. Requests that
omit execution controls keep their original serialized shape and request identity.
Saved 16.2 receipts retain their original shape and hashes on read-back: new
optional fields are omitted when absent from the original receipt. A receipt
fixture generated by untouched main verifies exact round-trip compatibility.
Reproducing old engine outputs still requires the retained code/dependency version.

Assumptions have a separate SHA-256 fingerprint over canonical versioned settings.
Equivalent Decimal spellings normalize identically. Run fingerprints bind modeled
assumptions and original book identity/time mapping. Historical receipts also bind
request, temporal policy, accounting settings, complete captured configuration,
source evidence and output archives independently. These hashes identify content,
not authenticity, ownership or licensing.

Omitting `paper` selects the original baseline. Replay accounting monetary inputs
also reject binary floats; existing `ResearchVaultConfig` bounds still apply.
No operational settings or venue metadata are inferred from these assumptions.

## Deterministic observation processing (16.3B)

- Order eligibility is creation receipt time plus configured latency. Execution
  requires a book observation received at or after eligibility and no later than
  evaluation. No interpolation or synthetic market events are introduced. Carried
  older books cannot fill orders that became eligible later.
- At each available observation, due cancellations settle before crossing fills.
  Cancellation wins an exact time tie. Repeated cancel requests retain the first
  deadline. A still-pending order remains OPEN/PARTIALLY_FILLED and included in
  capital/exposure reservation; it can fill before its cancellation deadline.
- Pending replacement cancellation defers submission. A later reconciliation
  generates and authorizes the replacement anew. Direct adapter replacement also
  defers; there is no queued future replacement or independent timer worker.
  Final modeled results expose outstanding `pending_cancellation_deadlines`.
- Only crossing orders qualify. Modeled prices start from the opposite observed
  BBO or retained level, adjusted adversely by configured slippage. A fill cannot
  exceed its authorized limit price. Insufficient price/size evidence yields no
  fill, not extrapolated liquidity.
- Both depth modes cap fills by observed size. With depth disabled, only the best
  level contributes. With depth enabled, the model walks strictly ordered retained
  levels. It never extrapolates outside recorded levels. Participation scales
  those budgets; partial-fill fraction caps each order's attempt. Zero budgets
  yield zero fills. Disabling partial fills consumes no depth on a failed attempt.
- Orders consume shared per-side/per-level budgets in stable submission order.
  This is a hypothetical allocator, not evidence of venue queue priority. Each
  order attempts a book observation at most once, preventing repeated fractional
  fills from the same snapshot. The runner passes original observation identity
  and receipt time, so a context-only frame cannot replenish old L2.
- Missing, stale, nonfinite, unsorted, wrong-market or inconsistent BBO/L2 evidence
  cannot create a modeled fill. All recorded observations remain immutable.
- Existing receipt-time batching preserves ties and sequence without jitter.
  Missing source timestamps stay unknown. Complete economics, age bounds,
  declared gaps, observer/generation changes and unavailable-frame resets retain
  the Phase 16.2 policy. No order, pending cancellation, depth budget, funding,
  inventory, markout or accounting state crosses a segment boundary.

These are deterministic sensitivities, **not calibrated predictions**. There is
no claim about actual queue position, unobserved trades, hidden liquidity,
unobserved replenishment, continuous coverage, real passive fills or actual
latency. Modeled crossing fills use a hypothetical taker fee classification;
receipt clocks are not exchange source clocks. Unknown source time is preserved,
not promoted into verified venue evidence.

## Accounting and comparisons (16.3C)

Each consumed level emits a normal existing `Fill` through the original callback:
telemetry, accounting trade/fee ingestion, execution consistency and acknowledgement.
A deterministic modeled source identity binds book and level, keeping equal-time
partial fills distinct in the existing accounting ledger. No timestamp jitter,
parallel ledger or accounting engine is added. Level prices and sizes use Decimal
multiplication directly; no rounded VWAP division loses trade notional. Existing
average-cost accounting, realized/unrealized PnL, fees, sampled funding, capital
reservation, exposure and risk drawdown consume those same fills.

Venue-derived evidence remains in original observation/provenance fields (or
explicit synthetic fixture labels). User assumptions stay in execution/accounting
configuration and separate fingerprints. Outputs are labeled hypothetical PAPER.
Fees use existing configured PAPER rates. Funding uses admitted rates under the
existing sampled research-interval convention, never an inferred venue payment.
Absent economics are rejected; conflicting fill economics still latch accounting
failure. Reference/risk conditions may legitimately result in zero authorized
orders and zero fills, as in the historical acceptance fixtures.

Every modeled replay segment retains its complete existing SimulationResult
archive plus a separately fingerprinted baseline archive using the identical
segment dataset, strategy, agents, risk and accounting inputs. Only execution
controls differ. Per-segment fill-count and session-PnL differences are checked
against those archives. There is no aggregate uninterrupted return across gaps.
Both passes start independently with the same capital; no output is fed into the
other pass. Archives preserve the existing engine's output retention bounds
(including its 500-entry returned ledger window), not an unlimited new ledger.
Reconciliation action metrics retain their existing intent-based interpretation;
repeated deferred replacement intents can contribute churn without transmission.

## Limits

No acquired/authenticated licensed native history, live-provider experiment,
real passive-fill or queue calibration, production latency benchmark, worst-case
performance certification, real Redis/multiprocess crash soak or frontend
acceptance is claimed. Fixtures and controlled deterministic scenarios establish
software behavior, not predictive market accuracy. Default SOL scenario strategy
scaling may be risk-suppressed; direct SOL adapter/accounting acceptance exercises
nonzero fills without relaxing production risk. Modeled comparison doubles bounded
per-segment computation/output; existing 5,000-frame/32-segment request bounds and
retention limits remain. The pre-existing POSIX storage trust limits apply.
Results still require caller retention; no research job store or persistence layer
is added. The PR remains draft and must not merge automatically.
